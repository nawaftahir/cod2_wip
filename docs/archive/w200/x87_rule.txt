RULE 1 (PINNED in the harness, CG_DrawLagometer): a value computed in the SAME basic block as the
  multiply is consumed: it is the "fld" side, the other operand becomes the memory operand
  (retail `fsub [a]; fmul [scale0]`). A value defined in an EARLIER block (a named local assigned before a
  switch/if/loop boundary) is treated like a variable: the other operand gets fld, the value stays on the
  stack (`fld [scale0]; fmul st(1) ... fstp st(0)`). One boundary is enough, even a constant
  `switch (3) { case 3: ... }`: with the screen_placement.inl switch, x (defined before the switch) is
  always kept; `do { } while (0)` (no real boundary) keeps the consumed form.
  Evidence (lag2.py): the snapshot site written as straight code `x = ...; x = sp0 * x + max0;` -> fmul [sp0];
  the same plus `switch (3) {case 3:}` around it -> fld sp0; x's def moved inside the case -> fmul [sp0].
  Declaration order (24 perms), x spelling (4 forms), color-select position (5), nosplit/x*s forms of the
  inl case 3: no effect, because none of them moves x's def across the switch boundary.
