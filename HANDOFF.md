## Structure facts that drive everything (details in RULES.md)
1. **One unity compile unit.** All game C++ files are `#include`d into one unit (`src/unit.cpp`,
   generated by `tools/gen_unit.py` from `link/order.txt`). Proof: register-argument `static` calls cross files,
   and 0x44f5d0 was reproduced byte-identical that way (`research/richtest/unity_test.cpp`).
   - Plain `/O2` gives register arguments ONLY to `static` functions. So any function that reads
     eax/edx/esi/edi/ebx on entry is `static` in its file (`data/ltcg.tsv` lists 854 of them).
2. Game C++ is plain `/O2 /Oy- /Op` (RTTI names exist; no prodid 100). 104 `/GL` C objects exist but add
   no code at the start of `.text`; where they are is still unknown and low priority.
3. zlib 1.1.4 + IW unzip: separate plain C files after the unit (`src/zlib`, pinned vs the official release).
4. Resources: `src/res/CoD2Radiant.rc` gives all 172 resources byte-identical. Assets are extracted to build/res.
5. Link: no `/OPT` (retail keeps identical functions apart), `/DEBUG`, PDB `e:\trees\cod2\bin\CoD2Radiant.pdb`
   (Wine's E: is mapped into build/).

## Commands
`make show A=0x...` · `make try S=src/file.cpp A=0x...` (compiles the whole unit) · `make verify` ·
`make build` (link + linkcheck) · `make sections` · `make meter` · `tools/ci_local.sh` (gate + Discord) ·
`python3 tools/units.py` · `python3 tools/ltcg_scan.py` · `python3 tools/rescheck.py`.
Everything runs in the image `cod2-radiant-msvc71` (`toolchain/build.sh`). Files written by Docker come out
root-owned. Chown them back (`docker run --rm -v $PWD:/w alpine chown -R $(id -u):$(id -g) /w/build /w/src /w/ledger`).

## Gotchas
- After editing a script with a Windows editor, `chmod +x tools/*.sh fleet/*.sh` (the exec bit gets lost).
- `fleet.sh start` refuses while loops still run; `fleet.sh stop` waits for the current batch.
- Commit identity Nawaf, no Co-Authored-By. Push only on the owner's "push it" (the lander pushes landings).
